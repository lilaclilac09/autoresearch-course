三文件架构

边界即设计——这个 repo 只有三个关键文件。但这三个文件的边界划分，决定了整个系统的运作方式。

三文件，三种角色

把这个系统想象成一场标准化科学实验：实验设备必须统一（不能私自修改仪器刻度）；实验变量是你真正要调的；实验方案是研究员在实验前写下的研究计划。

🔒
prepare.py

固定基础设施 — 数据下载、BPE 分词器训练、数据加载器、evaluate_bpb 评估函数。AI 代理不能修改这里的任何内容。 固定不变是这里的核心设计意图——它保证了实验之间的可比性，也是系统诚信的根基。

⚗️
train.py

实验目标 — GPT 模型架构、MuonAdamW 优化器、训练循环。这是唯一被 AI 代理编辑的文件。 一切超参数、架构选择都是公平的实验变量。每次实验，AI 代理从这里出发，改动，运行，记录结果。

📋
program.md

研究组织代码 — 人类定义实验目标、边界、循环规则。这是人类的杠杆：通过迭代 program.md 来改进 AI 的研究能力。它不是代码，而是"指令集"——告诉 AI 代理这场研究游戏的规则是什么。

prepare.py — 为什么不能动？

固定 evaluate_bpb 的评估逻辑是整个系统诚信的根基——如果 AI 能修改评估函数，它可以轻松"作弊"让数字变好看，但模型并没有真正改善。

prepare.py # 固定常量 — 不可修改 MAX_SEQ_LEN = 2048 # 上下文长度 TIME_BUDGET = 300 # 训练时间预算（秒） EVAL_TOKENS = 40 * 524288 # 验证集 token 数 VOCAB_SIZE = 8192 # BPE 词表大小 # 数据集：climbmix-400b-shuffle BASE_URL = "https://huggingface.co/..." VAL_SHARD = 6542 # 固定验证分片 def evaluate_bpb(model, dataloader): # ← AI 代理永远不能改这里 ...
逐行解读
MAX_SEQ_LEN = 2048
每个训练样本的最大 token 长度，决定模型能"看到"多长的上下文。
TIME_BUDGET = 300
固定 5 分钟时间预算。每个实验都跑同样长的时间，结果才有可比性。
EVAL_TOKENS = 40 × 524288
验证集大小固定在约 2100 万 token，确保每次评估结果一致，不会因为样本数不同而偏差。
VAL_SHARD = 6542
始终用同一个验证分片，彻底杜绝"数据泄露"：训练集和验证集严格分离。
evaluate_bpb 函数
这是"地面真相"（ground truth）。AI 改不了它——这一条保证了整个系统的诚信性。
🔏
为什么这条规则如此关键？

如果 AI 代理能修改 val_bpb 的计算方式，它可以让任何糟糕的模型看起来"更好"。固定评估函数的意义就在于：实验结果是真实的，不是被"优化"出来的幻觉。

train.py — 超参数直接写死在代码里

没有 CLI 参数，没有 YAML 配置文件。超参数就是 Python 变量，AI 代理直接改代码——简单、直接、易于 diff 追踪。

train.py # 模型架构 DEPTH = 8 # Transformer 层数 ASPECT_RATIO = 64 # model_dim = depth × this HEAD_DIM = 128 # attention head 维度 WINDOW_PATTERN = "SSSL" # 注意力窗口模式 # 优化 TOTAL_BATCH_SIZE = 2**19 # ~524K tokens/step EMBEDDING_LR = 0.6 # 词嵌入学习率 MATRIX_LR = 0.04 # 矩阵参数学习率（Muon） WEIGHT_DECAY = 0.2 WARMDOWN_RATIO = 0.5 # 学习率衰减时长比例 # 硬件 DEVICE_BATCH_SIZE = 128
逐行解读
DEPTH=8 + ASPECT_RATIO=64
→ Transformer 的隐藏维度 model_dim = 8 × 64 = 512。改成 DEPTH=12 则 model_dim = 768，模型容量大幅提升。
WINDOW_PATTERN = "SSSL"
大部分层（S）用短窗口注意力，节省算力；最后一层（L）强制用全上下文，捕捉长距离依赖。
TOTAL_BATCH_SIZE = 219
约 52.4 万 token 每步。若 batch size 超出显存，通过 gradient accumulation 自动拆分，train.py 内部处理，无需手动调整。
EMBEDDING_LR=0.6 / MATRIX_LR=0.04
两套 LR：词嵌入用 AdamW（LR=0.6），矩阵权重用 Muon 优化器（LR=0.04）。
WARMDOWN_RATIO = 0.5
Warmdown 占训练总时长的 50%。后半段学习率线性衰减到 0，现代 LLM 训练的标准做法。
💡
为什么不用 CLI 参数或配置文件？

让超参数直接活在代码里，意味着每次 git diff 都能清晰地看到"这次实验改了什么"。这个设计选择本身就是一种简洁性准则的体现——少一层抽象，少一个出错的地方。
