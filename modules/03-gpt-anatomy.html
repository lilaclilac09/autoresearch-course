Anatomy of a Modern GPT

What's actually packed into train.py? — Cracking open a race-car engine: every part has a reason to be there, every improvement is backed by a paper.

Eight modern improvements at a glance

The GPT in train.py is not 2019's GPT-2. It's a careful mix of 8 improvements that Karpathy hand-picked from 2024–2025 frontier research. Each improvement is an independent experimental knob — turn off Value Embedding, switch the SSSL pattern, change the softcap value, all are fair game.

⚡
RMSNorm

Replaces LayerNorm — simpler and faster, no mean computation needed. The standard choice for modern LLMs; used in LLaMA and Mistral.

🔄
RoPE

Rotary positional embeddings — encodes position by rotating Q/K vectors instead of adding to them. Extrapolates to lengths unseen during training.

🗂️
GQA

Grouped query attention — fewer K/V heads than Q heads, shrinks KV cache, enables larger batch sizes in training.

🔀
Value Embedding

A ResFormer improvement: injects token embedding info into the V vector, enabled on alternating layers, with a gate controlling the mix ratio. Improves gradient flow.

🪟
Sliding-window attention

SSSL pattern: most layers only see the first half of the sequence (efficient), the last layer is forced to see the full sequence — balances efficiency and global view.

📐
Squared ReLU

MLP activation uses relu² — sparser than GELU (more exact zeros), faster to compute, and empirically just as good or better.

🧢
Softcap logits

From Gemma 2: tanh-based soft truncation of logits, preventing numerical blowup that destabilizes training. Smoother than a hard clip.

🧭
Muon optimizer

Gradient-orthogonalizing optimizer — uses Newton-Schulz iteration to make every update step "maximally distinct", avoiding repeated movement in the same direction.

🔬
The AI agent's experimental space

Each of these 8 improvements maps to a hyperparameter or toggle. The AI agent can systematically enable/disable each improvement and measure its impact on MFU and validation loss, automatically producing ablation reports.

Attention trio: GQA + Value Embedding + RoPE

Three improvements work together to form the attention core in train.py. On the left is the simplified actual code; on the right, a line-by-line explanation.

Python # QKV projection (GQA: K/V heads can be fewer) q = self.c_q(x).view(B, T, n_head, head_dim) k = self.c_k(x).view(B, T, n_kv_head, head_dim) v = self.c_v(x).view(B, T, n_kv_head, head_dim) # Value Embedding (only on alternating layers) if ve is not None: gate = 2 * torch.sigmoid( self.ve_gate(x[..., :32])) v = v + gate.unsqueeze(-1) * ve # RoPE rotary positional embedding q = apply_rotary_emb(q, cos, sin) k = apply_rotary_emb(k, cos, sin) # QK norm (prevents attention-weight blowup) q, k = norm(q), norm(k) # Flash Attention 3 (hardware acceleration) y = fa3.flash_attn_func( q, k, v, causal=True, window_size=window_size)
Line-by-line
q / k / v shape difference
q has shape (B, T, n_head, head_dim); k/v have shape (B, T, n_kv_head, head_dim). The clever bit of GQA: when n_kv_head < n_head, multiple Q heads share one K/V group, cutting down both KV cache and compute.
ve_gate: input-driven mix gate
Computes a gate value from the first 32 dimensions of input x (sigmoid output 0–1, multiplied by 2 to give range 0–2), controlling how much Value Embedding to mix into the current v vector. Since the gate depends on the input, the model adaptively decides how much "raw embedding info" each token needs.
apply_rotary_emb: position via rotation
Pairs up dimensions of q/k and rotates each pair by an angle that depends on the token's position. When two positions are at a fixed relative distance, their dot product naturally reflects that relative distance — no extra positional embedding table needed, and it generalizes to longer sequences than seen during training.
window_size: SSSL sliding window
In the SSSL pattern, S layers only see the first half of the sequence (window_size = T/2), L layers see all of it (window_size = T). Flash Attention 3 handles the sliding window directly in the kernel — no Python-level masking required.
🔄
RoPE intuition: rotation = relative position

Say token A is at position 3 and token B is at position 7 — relative distance is 4. RoPE rotates qA by 3θ and kB by 7θ; their dot product contains (7−3)θ = 4θ, which depends only on relative position. Traditional learned positional embeddings can't do this, and positions never seen during training can still be rotated — that's why RoPE "extrapolates".

MLP + advanced stability tricks: Squared ReLU, Softcap, ResFormer residuals

Beyond the attention layer, train.py modernizes the MLP activation, output normalization, and residual connections. These three changes each look small, but together they make training more stable and help gradients flow deeper.

Python # MLP: Squared ReLU class MLP(nn.Module): def forward(self, x): x = self.c_fc(x) x = F.relu(x).square() # relu² x = self.c_proj(x) return x # Softcap (from Gemma 2) softcap = 15 logits = softcap * \ torch.tanh(logits / softcap) # ResFormer residual mix x = self.resid_lambdas[i] * x + \ self.x0_lambdas[i] * x0
Line-by-line
relu² (Squared ReLU)
Sparser than GELU — many activations are exactly 0 (only positive values are kept, and they're squared). Faster to compute. Experimentally, it's as good or better than GELU, with no GELU approximation error.
softcap: softly pins logits to [−15, 15]
In raw backpropagation, unbounded logit growth saturates softmax and kills gradients. softcap softly caps with tanh rather than hard-clipping — derivatives exist everywhere, gradient flow stays intact, and training stability improves significantly.
resid_lambdas: residual scaling
Each layer independently learns a scaling factor, initialized to 1.0 (equivalent to standard residual connections). During training the model can adapt the residual strength per layer.
x0_lambdas: original-embedding injection
x0 is the layer-0 input (raw token embedding). Every layer mixes in a small amount of x0 (initially 0.1), ensuring deep layers can still access the original semantic info — improving deep gradient flow.

MuonAdamW optimizer: make gradients orthogonal

🧭
Muon: orthogonalize the gradient

Standard SGD/Adam use the gradient directly to update weights. Muon first projects the gradient matrix onto orthogonal directions — using Polar Express Newton-Schulz iteration to compute the orthogonalized matrix — then updates. This makes every update "maximally distinct" from previous ones, avoiding repeated motion in the same direction, equivalent to a steepest-descent step in weight-update space.

Python param_groups = [ # AdamW handles embeddings and scalars dict(kind='adamw', params=embedding_params, lr=EMBEDDING_LR * dmodel_lr_scale, betas=ADAM_BETAS), # Muon handles matrix params dict(kind='muon', params=matrix_params, lr=MATRIX_LR, momentum=0.95, ns_steps=5), # N-S iteration count ]
Line-by-line
AdamW handles "non-matrix" params
token embeddings (wte), lm_head, resid_lambdas, x0_lambdas — these are vectors or scalars, can't be matrix-orthogonalized, so they keep using AdamW.
Muon handles all 2D matrices
Attention layers' c_q / c_k / c_v / c_proj, and the MLP's c_fc / c_proj — all 2D weight matrices. After orthogonalization, every update direction is "maximally distinct" from prior steps.
dmodel_lr_scale = (dim / 768)−0.5
Following μP (maximal update parametrization) theory, as model dim grows, the LR should shrink. This scaling factor lets models of different sizes train in the same reasonable LR range.
ns_steps=5: Newton-Schulz precision
5 Polar Express iterations are enough to give a sufficiently accurate orthogonalization. Each iteration computes a matrix polynomial; convergence is superlinear (5 steps brings error to negligible).
1
Adam: momentum + adaptive LR

Maintains first/second moment estimates of the gradient and adjusts per-parameter step size. Direction is decided by the raw gradient — may oscillate across correlated dimensions.

2
Muon: orthogonal gradient → update

First compute an orthogonalized version G_orth of the gradient matrix G (Newton-Schulz iteration), then apply momentum on G_orth. Every step walks "a new path" through weight space.

3
Use both, each for its job

Matrix params use Muon (benefit from orthogonal directions); non-matrix params use AdamW (not orthogonalizable, traditional route). Hence the name MuonAdamW.
