为什么"固定 5 分钟"是天才设计？

⏱️
时间预算而非步数预算

不管你把模型改大还是改小，batch size 加倍还是减半，每次实验都精确跑 5 分钟。 这让不同架构的实验直接可比，不需要手动对齐训练步数。 大模型每步慢，但 5 分钟内它仍然和小模型站在同一起跑线上竞争。

每次实验结束后，autoresearch 输出一份结构化的指标报告。 关键指标是 val_bpb（验证集每字节比特数），它与 BPE 词表大小无关，可以跨架构直接比较。

结果输出示例 --- val_bpb: 0.997900 training_seconds: 300.1 total_seconds: 325.9 peak_vram_mb: 45060.2 mfu_percent: 39.80 total_tokens_M: 499.6 num_steps: 953 num_params_M: 50.3 depth: 8
中文解释
val_bpb： 验证集每字节比特数，越低越好，不受词表大小影响
training_seconds：实际训练时长，固定约 300 秒（5 分钟）
total_seconds：含数据加载等额外开销的总耗时
peak_vram_mb： GPU 显存峰值用量，单位为 MB
mfu_percent：模型 FLOPs 利用率，衡量 GPU 算力的实际使用效率
total_tokens_M：本次训练消耗的 token 总量（百万）
num_params_M：模型参数量（百万）
depth： Transformer 层数，越深模型表达能力越强，但也越慢
💡
结果如何记录？

三文件架构

边界即设计——这个 repo 只有三个关键文件。但这三个文件的边界划分，决定了整个系统的运作方式。

三文件，三种角色

把这个系统想象成一场标准化科学实验：实验设备必须统一（不能私自修改仪器刻度）；实验变量是你真正要调的；实验方案是研究员在实验前写下的研究计划。

🔒
prepare.py

固定基础设施 — 数据下载、BPE 分词器训练、数据加载器、evaluate_bpb 评估函数。AI 代理不能修改这里的任何内容。 固定不变是这里的核心设计意图——它保证了实验之间的可比性，也是系统诚信的根基。

⚗️
train.py

实验目标 — GPT 模型架构、MuonAdamW 优化器、训练循环。这是唯一被 AI 代理编辑的文件。 一切超参数、架构选择都是公平的实验变量。每次实验，AI 代理从这里出发，改动，运行，记录结果。

📋
program.md

研究组织代码 — 人类定义实验目标、边界、循环规则。这是人类的杠杆：通过迭代 program.md 来改进 AI 的研究能力。它不是代码，而是"指令集"——告诉 AI 代理这场研究游戏的规则是什么。

prepare.py — 为什么不能动？

固定 evaluate_bpb 的评估逻辑是整个系统诚信的根基——如果 AI 能修改评估函数，它可以轻松"作弊"让数字变好看，但模型并没有真正改善。

VAL_SHARD = 6542 # 固定验证分片 def evaluate_bpb(model, dataloader): # ← AI 代理永远不能改这里 ...
逐行解读
MAX_SEQ_LEN = 2048
每个训练样本的最大 token 长度，决定模型能"看到"多长的上下文。
TIME_BUDGET = 300
固定 5 分钟时间预算。每个实验都跑同样长的时间，结果才有可比性。
EVAL_TOKENS = 40 × 524288
验证集大小固定在约 2100 万 token，确保每次评估结果一致，不会因为样本数不同而偏差。

evaluate_bpb 函数
这是"地面真相"（ground truth）。AI 改不了它——这一条保证了整个系统的诚信性。
🔏
为什么这条规则如此关键？

如果 AI 代理能修改 val_bpb 的计算方式，它可以让任何糟糕的模型看起来"更好"。固定评估函数的意义就在于：实验结果是真实的，不是被"优化"出来的幻觉。

train.py — 超参数直接写死在代码里

没有 CLI 参数，没有 YAML 配置文件。超参数就是 Python 变量，AI 代理直接改代码——简单、直接、易于 diff 追踪。

train.py # 模型架构 DEPTH = 8 # Transformer 层数 ASPECT_RATIO = 64 # model_dim = depth × this HEAD_DIM = 128 # attention head 维度 WINDOW_PATTERN = "SSSL" # 注意力窗口模式 # 优化 TOTAL_BATCH_SIZE = 2**19 # ~524K tokens/step EMBEDDING_LR = 0.6 # 词嵌入学习率 MATRIX_LR = 0.04 # 矩阵参数学习率（Muon） WEIGHT_DECAY = 0.2 WARMDOWN_RATIO = 0.5 # 学习率衰减时长比例 # 硬件 DEVICE_BATCH_SIZE = 128
逐行解读
DEPTH=8 + ASPECT_RATIO=64
→ Transformer 的隐藏维度 model_dim = 8 × 64 = 512。改成 DEPTH=12 则 model_dim = 768，模型容量大幅提升。
WINDOW_PATTERN = "SSSL"
大部分层（S）用短窗口注意力，节省算力；最后一层（L）强制用全上下文，捕捉长距离依赖。
TOTAL_BATCH_SIZE = 219
约 52.4 万 token 每步。若 batch size 超出显存，通过 gradient accumulation 自动拆分，train.py 内部处理，无需手动调整。
EMBEDDING_LR=0.6 / MATRIX_LR=0.04
两套 LR：词嵌入用 AdamW（LR=0.6），矩阵权重用 Muon 优化器（LR=0.04）。
WARMDOWN_RATIO = 0.5
Warmdown 占训练总时长的 50%。后半段学习率线性衰减到 0，现代 LLM 训练的标准做法。
💡
为什么不用 CLI 参数或配置文件？

让超参数直接活在代码里，意味着每次 git diff 都能清晰地看到"这次实验改了什么"。这个设计选择本身就是一种简洁性准则的体现——少一层抽象，少一个出错的地方。

03

现代 GPT 解剖

train.py 里塞了什么？——拆开一辆赛车引擎，每个零件都有存在的理由，每个改进都有论文支撑

8 项现代改进总览

train.py 里的 GPT 不是 2019 年的 GPT-2。它是 Karpathy 从 2024–2025 年最前沿的研究中精心挑选的 8 项改进的集合体。 每一项改进都可以被 AI 代理单独实验——关掉 Value Embedding，换掉 SSSL 模式，改变 softcap 值，全都可以测试。

⚡
RMSNorm

替代 LayerNorm，更简单更快，无需计算均值。现代 LLM 的标准选择，LLaMA / Mistral 均采用。

🔄
RoPE

旋转位置编码，通过旋转 Q/K 向量而非加法注入位置信息，可外推到训练时未见过的长度。

🗂️
GQA

分组查询注意力，K/V 头数可以少于 Q 头数，减少 KV 缓存，可在更大 batch 下训练。

🔀
Value Embedding

ResFormer 改进：向 V 向量注入 token 嵌入信息，交替层启用，用门控调节混合比例，改善梯度流。

🪟
滑动窗口注意力

SSSL 模式：大多数层只看前半段序列（高效），最后一层强制看完整序列，平衡效率与全局感知。

📐
Squared ReLU

MLP 激活函数用 relu²，比 GELU 更稀疏（更多精确零值），计算更快，实验效果相当甚至更好。

🧢
Softcap logits

来自 Gemma 2：用 tanh 软性截断 logits，防止数值爆炸导致训练不稳定，比硬 clip 更平滑。

🧭
Muon 优化器

梯度正交化优化器，用 Newton-Schulz 迭代让每步更新"最大程度地不同"，避免重复走相同方向。

🔬
AI 代理的实验空间

这 8 项改进每一个都有对应的超参数或开关。AI 代理可以系统性地开启/关闭每项改进，测量其对 MFU 和验证损失的影响，自动生成消融实验报告。

注意力机制三件套：GQA + Value Embedding + RoPE

三项改进协同工作，共同构成 train.py 的注意力核心。左侧是简化后的实际代码，右侧是逐行中文解释。

Python # QKV 投影（GQA：K/V 头可以更少） q = self.c_q(x).view(B, T, n_head, head_dim) k = self.c_k(x).view(B, T, n_kv_head, head_dim) v = self.c_v(x).view(B, T, n_kv_head, head_dim) # Value Embedding（交替层才有） if ve is not None: gate = 2 * torch.sigmoid( self.ve_gate(x[..., :32])) v = v + gate.unsqueeze(-1) * ve # RoPE 旋转位置编码 q = apply_rotary_emb(q, cos, sin) k = apply_rotary_emb(k, cos, sin) # QK 归一化（防注意力权重爆炸） q, k = norm(q), norm(k) # Flash Attention 3（硬件加速） y = fa3.flash_attn_func( q, k, v, causal=True, window_size=window_size)
逐行解读
q / k / v 的形状差异
q 的形状是 (B, T, n_head, head_dim)；k/v 的形状是 (B, T, n_kv_head, head_dim)。 GQA 的妙处：n_kv_head < n_head 时，多个 Q 头共享同一组 K/V 头， KV 缓存 和计算量同步减少。
ve_gate：输入驱动的混合门控
用输入 x 的前 32 个维度计算一个门控值（sigmoid 输出 0–1，乘 2 使范围变为 0–2），控制有多少 Value Embedding 被混入当前的 v 向量中。门控值依赖输入内容，让模型自适应决定每个 token 需要多少"原始嵌入信息"。
apply_rotary_emb：位置通过旋转编码
把 q/k 的向量维度两两配对，按 token 位置对应的角度旋转。两个位置相对距离固定时，它们的点积自然反映相对位置——无需额外的位置嵌入表，且可推广到训练时未见的更长序列。
window_size：SSSL 滑动窗口
SSSL 模式下，S 层只看前半段序列（window_size = T/2），L 层看全部（window_size = T）。 Flash Attention 3 直接在 kernel 层处理滑动窗口，无需在 Python 层做掩码。
🔄
RoPE 直觉：旋转 = 相对位置

设 token A 在位置 3，token B 在位置 7，相对距离是 4。RoPE 把 qA 旋转 3θ，kB 旋转 7θ， 它们的点积里包含的是 (7−3)θ = 4θ，只依赖相对位置。传统可学习位置嵌入做不到这一点， 而且训练时没见过的位置 index 可以继续旋转——这就是 RoPE 可以"外推"的原因。

MLP + 高级稳定技巧：Squared ReLU、Softcap、ResFormer 残差

注意力层之外，train.py 在 MLP 激活函数、输出归一化、残差连接三处都做了现代化升级。 这三处改进看似小，合在一起让训练更稳定、 梯度 流向更深。

Python # MLP：Squared ReLU class MLP(nn.Module): def forward(self, x): x = self.c_fc(x) x = F.relu(x).square() # relu² x = self.c_proj(x) return x # Softcap（来自 Gemma 2） softcap = 15 logits = softcap * \ torch.tanh(logits / softcap) # ResFormer 残差混合 x = self.resid_lambdas[i] * x + \ self.x0_lambdas[i] * x0
逐行解读
relu²（Squared ReLU）
比 GELU 更稀疏：大量激活值精确为 0（只有正值被保留，且正值被平方放大），计算更快。 实验表明效果相当甚至更好，且没有 GELU 的近似误差。
softcap：把 logits 软性锁在 [−15, 15]
原始 backpropagation 过程中，logits 无界增长会让 softmax 饱和、梯度消失。softcap 用 tanh 软性截断 而非硬 clip，导数处处存在，不破坏梯度流，训练稳定性显著提升。
resid_lambdas：残差缩放
每层独立学习一个缩放因子，初始化为 1.0（等同于标准残差连接）。 训练中模型可以自适应调整每层残差强度。
x0_lambdas：原始嵌入注入
x0 是第 0 层的输入（原始 token 嵌入）。每层都有少量 x0 混入（初始 0.1）， 确保深层仍能直接访问原始语义信息，改善深层梯度流。

MuonAdamW 优化器：让梯度正交

🧭
Muon：让梯度正交

标准 SGD/Adam 直接用 梯度 更新权重。Muon 先把梯度矩阵投影到正交方向——用 Polar Express Newton-Schulz 迭代计算正交化矩阵，然后再更新。 这让每步更新都"最大程度地不同"，避免重复走相同方向，等效于在权重更新空间做 steepest descent。

Python param_groups = [ # AdamW 管嵌入层和标量 dict(kind='adamw', params=embedding_params, lr=EMBEDDING_LR * dmodel_lr_scale, betas=ADAM_BETAS), # Muon 管矩阵参数 dict(kind='muon', params=matrix_params, lr=MATRIX_LR, momentum=0.95, ns_steps=5), # N-S 迭代次数 ]
逐行解读
AdamW 负责"非矩阵"参数
token 嵌入（wte）、lm_head、resid_lambdas、x0_lambdas 这些参数是向量或标量， 无法做矩阵正交化，因此继续用 AdamW 更新。
Muon 负责所有 2D 矩阵
注意力层的 c_q / c_k / c_v / c_proj，以及 MLP 的 c_fc / c_proj—— 这些都是二维权重矩阵，正交化后每步更新方向"最大化互不重复"。
dmodel_lr_scale = (dim / 768)−0.5
按照 μP（maximal update parametrization）理论，模型维度越大，学习率应越小。 这个缩放因子让不同规模的模型都能在同一个合理 LR 范围内训练。
ns_steps=5：Newton-Schulz 精度
Polar Express 迭代 5 次，即可达到足够精确的正交近似。 每步迭代计算一个矩阵多项式，收敛速度是超线性的（5 步足以让误差降至可忽略）。
1
Adam：动量 + 自适应 LR

累积一阶/二阶梯度矩估计，对每个参数独立调整步长。方向由原始梯度决定，可能在相关维度上重复振荡。

2
Muon：正交梯度 → 更新

先对梯度矩阵 G 计算正交化版本 G_orth（Newton-Schulz 迭代），再用 G_orth 做动量更新。每步更新在权重空间"走一条新路"。

3
两者并用：各司其职

矩阵参数用 Muon（受益于正交方向），非矩阵参数用 AdamW（不可正交化，走传统路线）。这就是 MuonAdamW 名字的由来。

实验循环与扩展：从零跑起来

快速上手：五步从零到第一次实验

🚀
部署一个无人值守的研究团队

把 autoresearch 想象成你雇了一支研究团队。你是 PI（首席研究员）， program.md 是你写给团队的研究方案。安排好一切后，你下班回家——团队彻夜工作，早上汇报结果。

1
安装 uv
uv 是比 pip 快 10–100x 的 Python 包管理器。先安装它，再同步依赖： 
curl -LsSf https://astral.sh/uv/install.sh | sh
uv sync
这一步只需做一次。
2
准备数据
下载 climbmix 数据集分片，训练 BPE 分词器——约 2 分钟，只需做一次： 
uv run prepare.py
完成后本地会有数据分片文件和分词器。
3
手动跑一次
跑一次完整训练，验证环境正常。大约 5 分钟后你会看到 val_bpb 输出： 
uv run train.py
这个数值就是你的 baseline，后续所有改进都以它为参照。
4
启动 AI 代理
在这个 repo 里打开 Claude 或 Codex CLI，发送启动提示词： 
"看一下 program.md，开始新实验！先做 setup。"
代理会读取 program.md， 查看 git 状态，然后开始第一轮实验循环。
5
去睡觉
AI 代理会自主循环，彻夜运行。早上检查 results.tsv，你会看到完整的实验日志——哪些 keep、哪些 discard、哪些 crash。 每次实验约 5 分钟，8 小时 ≈ 96 次实验。

如果崩溃怎么办？

如果 uv run train.py 崩溃（比如 OOM 显存溢出），代理会运行： tail -n 50 run.log 读取错误信息，然后在 results.tsv 记录 status=crash，执行 git reset 回到上个好状态，换一个更保守的想法重新实验。

如何写出好的 program.md？

📝
program.md 是你作为研究 PI 最重要的产出

它不只是指令——它是你对 AI 研究能力的编程。写得越好，AI 代理的实验就越有方向感，越少在低价值尝试上浪费预算。

program.md 写法对比 ❌ 差的 program.md： "试各种改进，找到 最好的 val_bpb" ✓ 好的 program.md： "优先探索： 1. 优化器超参调优 (LR, betas, warmdown) 2. 架构变体（GQA 比例） 3. 注意力模式（SSSL vs SSL） 如果连续 3 次 discard， 尝试方向性重置。"
为什么这样写？
差的写法：太模糊，AI 会随机游走，浪费大量实验预算在低价值尝试上，就像告诉一个新人"去把这个项目做好"。
好的写法：给出优先级和搜索空间的结构，相当于一个资深研究员告诉新人"从这里开始，按这个顺序探索"。
编码领域知识：例如"Muon 对学习率敏感，先在 0.02–0.06 范围内扫描"——这是你作为人类的核心价值。
简洁性准则：Karpathy 特意加入了"代码越简单越好"的要求，防止 AI 为了追求 val_bpb 而引入过于复杂的 trick。
NEVER STOP 规则：确保代理彻夜不停，就算在困难的搜索空间里也坚持迭代，不会等待人类指示。
🔄
program.md 本身也是可迭代的

你观察 AI 的研究行为，发现它在走弯路——比如总是调同一个参数——然后在 program.md 里加入约束或新方向。下次重启，它就会更聪明。 这是人类研究能力的编码化。

小硬件怎么跑？+ 更大的图景

💻
在 MacBook / 小 GPU 上跑 autoresearch

官方版需要 H100（80GB 显存）。但社区已有 macOS / AMD / Windows fork。在非 H100 机器上，关键调整：

  • DEPTH：从 8 降到 4——更浅的模型，显存大幅减少
  • TOTAL_BATCH_SIZE：从 219 降到 214（约 16K），降低每步 梯度累积 开销
  • WINDOW_PATTERN：改为 'L'（去掉短窗口 SSSL），在 MPS / CPU 上更高效
  • 替换数据集：考虑用 TinyStories 替代 climbmix，数据量小很多，小模型也能看到合理结果
  • 社区 fork：macOS 参考 miolini/autoresearch-macos，AMD 参考 andyluo7/autoresearch

更大的图景

autoresearch 只有三个文件、一块 GPU、一晚上——但它指向的是 AI 辅助科研的根本转变。

人类角色的转变

从"手动调参者"→"研究指令的作者"。核心能力变成：读懂结果、形成假设、把领域知识编码进 program.md。 Karpathy 的原话："肉体计算机做前沿 AI 研究的时代，已经过去了。"

AI 研究的边界

autoresearch 只优化一个指标（ val_bpb ）。真正的研究突破还需要人类提出正确问题、设计正确评估标准——这是目前 AI 无法替代的部分。

♻️
可复制的框架

这个三文件架构可以被复制到任何领域：量化交易策略迭代、药物分子优化、程序合成。 固定评估 + 可改目标 + 人写指令 = 普适模式。
